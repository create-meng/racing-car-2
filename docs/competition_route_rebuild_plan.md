# 比赛场地路线图与导航重构规划

本文根据比赛场地示意图、地图坐标图以及当前 `dating.csv`、`shunshizhen1.csv`、`test_1.csv` 制定。它描述的是比赛规则层面的路线约束和导航架构；本次只更新文档，不修改现有导航代码、CSV 坐标和 Nav2 参数。

## 1. 坐标与场地区域

- 地图范围：`5m × 5m`。
- 地图坐标原点：左下角 `(0, 0)`。
- 小车初始化位姿：`(0, 0, 0)`，即场地图中的 `P` 点。
- `x` 向右增加，`y` 向上增加。
- 静态地图是最终的硬约束，下面的边界数值只用于路线设计和日志解释，不能替代实际栅格地图。

### 区域定义

| 区域 | 约略坐标范围 | 导航规则 |
|---|---|---|
| 大厅 | `0 ≤ x ≤ 5，0 ≤ y < 2.0` | 动态锥桶较多，采用人工设计的参考路线；允许局部避让，但必须回到参考路线。 |
| 中央交接通道 | 约 `2.0 ≤ x ≤ 3.1，2.0 ≤ y ≤ 2.9` | 唯一合法的大厅↔诊疗室通道，只允许从中间黄色口进入或离开。 |
| 左侧黄白交叉区 | 约 `x < 2.0，2.0 ≤ y ≤ 2.5` | 禁止通行，由静态地图作为墙体处理。 |
| 右侧黄白交叉区 | 约 `x > 3.1，2.0 ≤ y ≤ 2.5` | 禁止通行，由静态地图作为墙体处理。 |
| 诊疗室外围黄色环带 | 约 `0.5 ≤ x ≤ 4.5，2.9 ≤ y ≤ 4.7`，扣除中间绿色区域 | 正常主路线；优先在黄色区域内行驶。 |
| 诊疗室绿色内部 | 约 `1.0 ≤ x ≤ 4.0，3.5 ≤ y ≤ 4.1` | 平时禁止/高惩罚；黄色路线被动态障碍堵住时，可作为受控临时绕行区，绕行后必须回到黄色路线。 |

示意拓扑如下：

```text
                         诊疗室外围黄色环带
                 ┌─────────────────────────┐
                 │   左环带 → 上环带 → 右环带 │
                 │        ┌─────────┐       │
                 │        │ 绿色低优先│       │
                 │        │ 动态绕行区│       │
                 │        └─────────┘       │
                 └───────────┬─────────────┘
                             │
                    唯一中间黄色通道
                             │
                 ┌───────────┴─────────────┐
                 │      大厅动态障碍区       │
                 │  P(0,0) → 人工参考路线    │
                 └─────────────────────────┘
```
## 2. 目前路线选择是否合理

大厅存在约 13 个动态障碍，使用人工布置参考路线是合理的，原因是：

1. 动态锥桶不属于固定地图，单纯依赖静态全局规划无法提前知道比赛时的实际摆放；
2. 大厅空间相对开阔，人工路线可以把车辆引导到预期的比赛行驶区域；
3. 大厅的动态避障应当是“围绕人工路线有限偏移”，而不是让全局规划器自由选择另一侧路线；
4. 手打路线可以作为路线图中的主边，激光只负责短距离避让和回线。

因此，`dating.csv` 以及二维码路线中位于大厅的部分不需要改成完全自动探索路线。需要改变的是执行方式：CSV 不再只是离散目标点，而是转换成带有路线走廊、速度和避障规则的参考边。

诊疗室区域则不同：黄色区域是正常主路线，绿色区域不是平时的路线，但不能简单设置成永远不可进入。黄色路线被动态障碍占用时，绿色区域可以作为受控临时绕行空间；绕行必须有触发条件、范围限制和回线条件，不能变成自由穿越诊疗室。

## 3. 路线图节点与边

路线图采用“节点 + 合法边”模型。CSV 坐标继续保留，作为节点锚点；运行前将其编译为路线图和稠密参考路径。

### 节点类型

| 节点类型 | 含义 | 完成规则 |
|---|---|---|
| `START_P` | 初始化点 `(0,0)` | 仅作为起点，不要求重新追踪。 |
| `HALL_ANCHOR` | 大厅人工路线锚点 | 进入精确半径或确认沿大厅参考线经过。 |
| `GATE_IN` | 中间黄色通道入口 | 必须从中央黄色口进入，禁止从左右黄白交叉区进入。 |
| `DIAG_ANCHOR` | 诊疗室黄色环带锚点 | 正常必须在黄色环带走廊内完成；仅在动态障碍触发时允许经过绿色临时绕行区后回线。 |
| `GATE_OUT` | 返回大厅的中央通道节点 | 只能通过中央黄色通道返回。 |
| `FINAL_RETURN` | 最终返回点，奇数路线当前定义为 `(0,0.1)` | 位置完成优先，航向按现有规则可忽略。 |

### 边类型

每条路线边需要包含：

```text
start_node
end_node
reference_path
corridor_width
speed_limit
normal_completion_radius
obstacle_completion_radius
allow_dynamic_detour
must_rejoin
```

建议规则：

| 边 | 路线约束 | 动态绕行 | 建议速度 |
|---|---|---|---:|
| 大厅直线边 | 参考线为主，允许较大局部偏移 | 允许，绕障后回线 | 0.45～0.55m/s |
| 大厅弯道边 | 跟随人工曲线 | 允许有限偏移 | 0.30～0.40m/s |
| 中央入口边 | 只能穿过中间黄色口 | 只允许很小偏移 | 0.18～0.30m/s |
| 诊疗室环带边 | 黄色区域为正常主路线 | 动态障碍触发时允许进入绿色临时绕行区，完成后必须回线 | 0.22～0.38m/s |
| 急弯边 | 禁止切角 | 必须先减速 | 0.20～0.30m/s |
| 最终返回边 | 保留路线完整性 | 可有限避障，不删除最终点 | 0.18～0.30m/s |

  → 左侧中央通道/诊疗室入口附近
  → (1.432, 2.902)
  → (0.424, 2.969)

这条路线不能被全局规划器理解成“从入口直接抄到右侧”，必须保留：

- 入口边；
- 左侧黄色环带边；

- 右侧黄色环带边；

- 仅由动态障碍触发；
- 只连接当前黄色边的入口和出口；
- 不允许跨越绿色区域后直接跳到无关节点；
- 通过障碍后必须回到黄色环带；
- 不能因为规划方便而长期选择绿色路线。

大厅人工段

  → 上侧黄色环带
  → 左侧黄色环带
  → 中央通道返回

该路线点数较多，不能按每个点单独重新规划；应当将相邻点编译为连续路线边，在急弯和中央通道位置增加精确节点。

## 5. 推荐的导航重构架构

### 5.1 使用 `nav2_route` 管理合法路线

当前系统已经安装 `nav2_route`，可以使用：

- `ComputeRoute`：预先计算路线；
- `ComputeAndTrackRoute`：计算并持续跟踪路线；
- 路线节点和路线边反馈；
- 路线边速度限制；
- 动态路线代价；
- 路线碰撞检查；
- 重新规划操作。

路线图的合法边只建立在：

1. 大厅人工参考路线；
2. 中间黄色通道；
3. 诊疗室外围黄色环带；
4. 规定的返回路线。

不建立以下边：

- 左右黄白交叉区；
- 从大厅直接穿越诊疗室内部的捷径；
- 从诊疗室两侧绕过中央黄色口的边。

绿色区域不建立普通主路线边，只建立受条件控制的临时绕行边。这样既能避免平时走绿色区域，也能在黄色线上出现动态障碍时保留安全出口。

### 5.2 使用 MPPI 负责局部动态避障

MPPI 继续作为局部控制器，但职责改为：

- 在当前合法路线边附近选安全轨迹；
- 避开实时激光锥桶；
- 遵守阿克曼转弯约束；
- 根据路线边速度限制调速；
- 遇到局部障碍后重新并入当前路线边。

MPPI 不能拥有“自由选择整张地图路线”的权限。路线图提供的 Path 和路线走廊必须成为高权重约束。

### 5.3 h1 只负责比赛规则，不再猜 Nav2 当前点

`h1.py` 的二维码识别保持不变，二维码之后的职责调整为：

- 选择奇数/偶数路线图；
- 记录当前路线节点和路线边；
- 根据 AMCL 计算点位完成；
- 判断是否真正沿路线经过节点；
- 处理动态障碍造成的有限绕行；
- 记录最终路线是否完整完成。

不能再使用 `NavigateThroughPoses` 的 `number_of_poses_remaining` 推断当前点，也不能让 `RemovePassedGoals` 单独决定比赛点位是否完成。

## 6. 点位完成与跳过规则

必须把下面三个概念分开：

### 正常精确完成

建议初始值：

```text
normal_completion_radius = 0.20～0.25m
```

要求 AMCL 连续若干帧保持在半径内。

### 障碍补偿完成

建议初始值：

```text
obstacle_completion_radius = 0.30～0.40m
```

但不能只看距离，还必须确认：

- 车辆沿规定路线方向已经越过节点；
- 节点已经落在车后方；
- 当前路线投影已经进入后续边；
- 当前点前方确实被障碍阻挡。

### 禁止的跳点方式

以下逻辑必须删除：

```text
超过 20 秒，无论是否经过，直接删除当前点
```

单点卡住时应优先：

```text
当前边局部重规划
→ 有限脱困
→ 重新并入当前边
→ 继续追当前点
→ 确认经过后再进入下一点
```

## 7. 大厅与诊疗室采用不同控制策略

### 大厅策略：人工路线 + 动态局部避障

大厅动态障碍多，不能把路线做成绝对窄走廊。

建议：

- 保留人工手打路线；
- 直线段速度最高可到 `0.45～0.55m/s`；
- 允许局部绕开动态锥桶；
- 绕行横向偏差设置为软上限；
- 障碍通过后必须回到人工参考路线；
- 不因单个锥桶直接切换到另一条全局路线。

### 诊疗室策略：黄色主路线 + 绿色受控绕行

诊疗室区域采用“黄色主路线、绿色临时绕行、黄白交叉区硬禁止”的三层规则：

- 黄色环带作为默认路线图；
- 黄白交叉区仍然是硬障碍，任何情况下都不能进入；
- 绿色区域平时施加高路线惩罚，不建立默认主路线；
- 黄色边被动态障碍堵住时，允许生成受限绿色绕行边；
- 绿色绕行必须从黄色边进入并回到黄色边；
- 中央通道仍然是大厅和诊疗室之间唯一出入口；
- 诊疗室内路线外偏差应明显高于大厅；
- 不能为了追点无条件穿越绿色区域。

静态地图必须与该规则一致：绿色区域要保持可被 costmap 检查的自由空间或低代价空间，不能被静态地图标成永久 lethal；黄色路线和黄白交叉区的实际墙体仍由静态地图提供。如果当前 `ai_map.pgm` 将绿色区域全部标成 lethal，就不能仅靠 h1 或 MPPI 实现绿色临时绕行，必须先调整地图语义或增加独立的区域代价层。

## 8. 脱困和动态障碍规则

### 253 代价

`253` 作为进入 inscribed 区域的预警：

- 先减速；
- 观察是否仍有路线进展；
- 尝试当前边局部绕行；
- 不立即删除当前节点。

### 254 代价

`254` 作为硬碰撞边界：

- 立即停止前进；
- 选择已通过 footprint 和激光检查的前进/倒车弧线；
- 脱困后重新寻找最近合法路线边；
- 保留尚未确认完成的节点。

### 过滤器进程

系统必须保证只有一个 `static_wall_scan_filter`。启动检查必须确认：

```text
/scan → 唯一过滤器 → /scan_nav
processed > 0
没有旧的 tf_passthrough 进程
没有重复发布者
```

否则全局/局部 costmap 对墙体和动态锥桶的判断会不一致，路线图再正确也无法稳定执行。

## 9. 实施顺序

### 阶段 A：只增加观测

记录：

- 当前路线节点和路线边；
- AMCL 到节点距离；
- 路线横向偏差；
- 当前边投影进度；
- 当前速度与边速度上限；
- 静态/动态 footprint 代价；
- 激光最小距离；
- 规划和控制耗时；
- 是否发生路线外偏移。

### 阶段 B：生成路线图

从现有 CSV 生成路线图：

- `shunshizhen1` 路线图；
- `test_1` 路线图；
- 需要时再生成 `dating` 路线图；
- 校验静态地图通行性；
- 生成稠密参考 Path；
- 标记入口、急弯、返回点和速度区。

### 阶段 C：只在 RViz 验证路线

确认：

- 路线节点顺序正确；
- 入口只有中央黄色口；
- 诊疗室默认路线不穿绿色内部；绿色临时绕行边必须明确标记并满足动态障碍触发条件；
- 左右黄白交叉区没有路线边；
- 返回路线不会追到身后点。

### 阶段 D：接入 MPPI

低速验证：

```text
0.20 → 0.30 → 0.40m/s
```

确认路线走廊和避障行为正确后，再提高直线段速度。

### 阶段 E：接入点位完成与脱困

最后才启用：

- 正常完成半径；
- 障碍补偿半径；
- 路线投影经过判定；
- 局部脱困；
- 动态障碍回线；
- 最终点严格完成。

## 10. 验收指标

### 路线纪律

- 不进入静态禁区；
- 平时不进入绿色区域；
- 只有黄色路线被动态障碍堵住时，才允许进入绿色临时绕行区；
- 绿色绕行后必须回到黄色路线；
- 不经过左右黄白交叉区；
- 只使用中央黄色通道；
- 动态绕行后回到规定路线；
- 路线索引不能回退；
- 不能追身后点。

### 精度

- 普通点误差目标：`≤ 0.22m`；
- 最终点误差目标：`≤ 0.20m`；
- 诊疗室横向偏差目标：`≤ 0.20～0.25m`；
- 障碍补偿只允许在经过条件满足时使用。

### 速度

- 大厅直线段目标：`0.45～0.55m/s`；
- 诊疗室普通边：`0.30～0.40m/s`；
- 急弯和入口：`0.20～0.30m/s`；
- 不用为了诊疗室的急弯降低整个路线的速度。

### 安全和稳定性

- 碰撞次数为 0；
- footprint 进入 `254` 次数为 0；
- 单个动态障碍不能导致整条路线停止；
- 无重复 action 目标；
- 无旧回调覆盖新任务；
- 无重复激光过滤器；
- 无 TF future/extrapolation；
- 全局和局部 costmap 持续发布。

## 11. 本次结论

大厅采用人工参考路线是正确方向，不需要改成完全自动探索；诊疗室采用黄色主路线、绿色受控绕行区和黄白交叉区硬障碍三层约束，中央黄色通道仍是唯一出入口。

最终重构方向确定为：

```text
大厅：人工参考路线 + MPPI 动态避障 + 回线
中央交接：唯一黄色通道硬约束
诊疗室：黄色环带主路线 + 绿色动态绕行边 + 黄白交叉区静态硬障碍
二维码：保持现有识别逻辑
导航执行：nav2_route + MPPI + 自定义点位/经过/脱困状态机
```

本文件是后续修改 `h1.py`、`nav.yaml`、行为树和启动文件的基准规划。

## 12. 第一批重构已落地

本批次先在现有 Nav2 action 链上落地最容易造成路线错乱的部分，二维码识别、大厅 `dating.csv` 和原始二维码 CSV 坐标保持不变：

- 二维码路线由整段 11/26 点一次发送改为最多 3 点短窗口；
- 当前 action 被取消或 `ABORTED` 时，先提交 feedback 已确认完成的窗口点，避免重复发送旧点；
- 删除行为树 `RemovePassedGoals` 的隐式删点，点位索引由路线客户端统一维护；
- 超时不再无条件跳点，只有确认沿路线经过后才允许推进；
- 正常底层目标容差收紧到约 `0.22m`；
